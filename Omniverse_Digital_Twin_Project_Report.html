Executive Summary: This technical dossier provides an exhaustive overview of the end-to-end development, architecture, physics instrumentation, and real-time streaming bridge engineered in this workspace. The system connects an Omniverse Kit headless GPU rendering server with a modern React (Vite + TypeScript) client over bidirectional WebRTC data and media channels, delivering an interactive industrial conveyor digital twin with live box counting, surface velocity physics, and dynamic telemetry.

1. Project Scope & Architecture Evolution

The initiative commenced as a bidirectional proof-of-concept allowing a web client to render a remote Kit viewport and spawn simple 3D primitives over a WebRTC data channel. Through a series of structured engineering sprints, the system was expanded into a high-fidelity industrial digital twin featuring realistic PhysX mechanics, dynamic asset authoring, and asynchronous push telemetry.

Phase 1: Bidirectional WebRTC Core

Established low-latency H.264 video streaming via @nvidia/ov-web-rtc AppStreamer, Kit event dispatching, and custom JSON data channels without external REST relays.

Phase 2: Conveyor Physics & Digital Twin

Broke out procedural and baked 3D conveyor assets, PhysX Surface Velocity belt mechanics, collision geometry, gravity timelines, and collection bin containment.

Phase 3: Real-Time Sensor Telemetry

Engineered continuous spatial arrival detection for delivered packages, spontaneous push notifications to the browser, and live box counter synchronization.

Phase 4: Resilience & Production Hardening

Implemented hardware H.264 codec pinning, Kit run-loop pacing (60 FPS), dynamic aspect ratio resizing, a decoded-frame watchdog, and instant stream reconnection.

4. USD Hierarchy & Physics Modeling

The simulation environment is authored natively in OpenUSD (Conveyor_Simulation.usda and binary .usd). The stage operates in standard centimeter units (metersPerUnit = 0.01) with a Y-Up coordinate convention, fully configured with realistic dynamic friction and mass distribution.

Prim Path USD Type & Schema Dimensions / Transforms Functional Role in Simulation
/World/PhysicsScene UsdPhysics.Scene Gravity: (0, -980, 0) cm/s² Defines global dynamic simulation parameters and gravitational vector.
/World/Conveyor/Belt Cube + PhysxSurfaceVelocityAPI Scale: (400, 10, 80), Elev: 80 cm Active moving belt. Imparts linear velocity along the +X axis (default 140 mm/s) to resting packages.
/World/Conveyor/Leg_0..2 Cube + PhysicsCollisionAPI Scale: (12, 75, 76) at X=-160, 0, +160 Heavy structural steel frame legs holding the conveyor bed at working height.
/World/Conveyor/Rail_0..1 Cube + PhysicsCollisionAPI Scale: (400, 22, 6) at Z=±44 cm Dual lateral side guide rails ensuring packages do not veer off under acceleration.
/World/Container/Floor Cube + PhysicsCollisionAPI Scale: (120, 6, 120) at X=275 cm Discharge receptacle base positioned below the head pulley to collect dropped packages.
/World/Container/Walls Cube (4 Perimeter Walls) Height: 55 cm, Safety Amber Enclosed bin perimeter preventing accumulated packages from scattering onto the factory floor.
/World/Packages/Box_* Cube + RigidBodyAPI + MassAPI Size: 32 cm³, Mass: 2.0 kg Dynamic package with random vibrant palette (gold, blue, neon green, coral orange, teal).

5. WebRTC Data Channel Messaging Contract

Communication between the React web client and Omniverse Kit occurs over named bidirectional JSON messages routed through the streaming data channel.

Event Identifier Direction Payload Structure Description
dropPackageRequest Browser → Kit {} Requests the server to spawn and drop a rigid-body package onto the conveyor intake.
dropPackageResult Kit → Browser {"result": "success", "path": "/World/Packages/Box_1"} Confirms package creation and passes the resulting USD prim path.
setConveyorSpeedRequest Browser → Kit {"speed": 220.0} Dynamically updates PhysxSurfaceVelocityAPI on the moving belt in real time.
setConveyorSpeedResult Kit → Browser {"result": "success", "speed": 220.0} Confirms that the new surface speed has been applied in PhysX.
containerCountUpdate Kit → Browser {"count": 7, "box_path": "...", "reset": false} Spontaneous push notification emitted immediately when a package enters the bin.
resetContainerRequest Browser → Kit {} Purges all active package prims from /World/Packages and zeroes the counter.

6. Production-Grade Performance Tuning & Anti-Freeze Protections

Real-time WebRTC streaming of high-density 3D viewports is susceptible to network jitter, decoder stalls, and frame-pacing irregularities. Six targeted optimizations were incorporated:

1. Hardware H.264 Codec Pinning

Explicitly forces VideoCodec.H264 on both client and Kit to prevent browser fallback to software VP8/VP9 decoders which cause severe frame stutter.

2. Kit Run-Loop Pacing

Enabled rateLimitEnabled = true with rateLimitFrequency = 60 in Kit to eliminate render jitter and prevent NVENC encoder pipeline starvation.

3. Dynamic Viewport Resizing

Configured dynamicResize = true in my_usd_viewer_streaming.kit so remote rendering resolutions dynamically adapt to browser dimensions.

4. Sdf.ChangeBlock() Coalescing

All procedural USD scene mutations are batched in change blocks to ensure Hydra constructs acceleration structures once rather than per-attribute.

5. Decoded Frame Watchdog

The React client interrogates getVideoPlaybackQuality().totalVideoFrames. If decoded frames halt while connected, a warning and auto-reconnect are triggered.

6. Zero-Reflow Pinned Layout

The HTML5 video container is styled with absolute inset positioning to isolate 60 FPS video frame repaints from the React DOM tree, eliminating layout thrashing.
